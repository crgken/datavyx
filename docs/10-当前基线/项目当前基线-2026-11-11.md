## 当前产品方向

AtlasAI 当前产品范围收窄为记录与查询：新增业务信息，检索对象及关系，追溯来源，执行精确统计。用户已明确不需要操作确认流程。

用户已选择先将当前线上知识管理能力通过 MCP 接入 ChatGPT，并明确由调用 Agent 生成结构化参数，后端无 LLM、无 Graphiti、直接连接 Neo4j。2026-11-12 已授权按单元计划开发，独立实现与隔离测试正在 `codex/mcp-neo4j` 分支推进，当前线上仍为旧系统；真实数据副本、ChatGPT 及正式上线不能用本地测试代替。实际状态见[开发进度](../50-运行记录/MCP改造开发进度-2026-11-12.md)。唯一详细设计见[完整 MCP 改造方案](../40-实施计划/AtlasAI知识管理MCP完整改造方案-2026-11-11.md)，原[简要规划入口](../40-实施计划/AtlasAI知识管理MCP规划-2026-11-11.md)继续保留。

首版 MCP 不提供更正、覆盖、删除、归档、恢复、审批或操作预览；记录直接保存，不设置待确认标志、确认卡或批准页面。登录和数据访问权限仍保留。

## 目标架构

- 调用方 Agent 负责意图、提取、同义词扩展、查询参数和最终回答；后端只做确定性存取与校验。
- 后端不运行内部 Agent、LLM、Graphiti、embedding 或 reranker；不将这些能力作为错误回退或后台索引任务。
- 首版搜索采用字段、关系、关键词和 Neo4j 全文索引，不承诺自动语义检索。
- 新增来源、对象/事实、幂等回执和审计在 Neo4j 事务中保存；不创建待确认/审批任务，不覆盖旧事实。
- 数据库凭据、Cypher 和空间授权保留在服务端，不能把“直接连接 Neo4j”理解为 Agent 直接获得数据库访问权。

## 已部署旧系统与复用边界

- `knowledge-management-demo`：当前知识管理服务，包括业务对象/事实、来源、精确查询、空间权限、变更授权、审计与索引任务。
- `knowledge-web-pwa`：现有网页入口。本次规划不要求新增确认页，也没有修改现有页面代码。
- 旧系统的 Neo4j 规范业务记录是精确查询和统计依据；旧 Graphiti 仍负责语义检索/投影。该事实不代表新 MCP 保留 Graphiti。
- 当前代码已有普通新增自动记录及受控修改机制；后者属于存量实现，不是首版 MCP 要开放或继续建设的能力。
- MCP 新增录入仍需权限、来源、幂等和真实保存回执；同名不自动合并，冲突内容不覆盖旧事实，相关精确统计排除冲突槽；source_only 可保存原文但不伪造结构化事实。
- 旧服务的 Store、索引任务、模型和草稿批准链路有耦合，新 MCP 必须独立拆分；旧聊天、语音、worker 和网页处置是正式切换的一部分，不能暗中保留模型调用却宣称改造完成。
- 本次方向归档未修改运行代码、数据库或线上部署，也未重新构建前端。

## 当前实施原则

1. 先隔离依赖及契约，验证 ChatGPT 接入、OAuth 和只读查询，再推进直接录入；不安排确认流程或存量修改阶段。
2. MCP 和网页复用同一业务服务及数据边界，不复制一套知识库。
3. 对话理解必须在调用方 Agent 完成，服务端执行数据访问权限、schema、空间范围、事务、来源和幂等校验，不调用模型补判。
4. 已确认的方向不等于实施完成；功能开发、迁移演练和正式发布按完整方案分阶段验证及 Git 流程推进。
5. 原规范数据、来源和 ID 优先兼容；旧未执行操作不激活，旧语义库封存清理另行处理，不提前删除数据。
