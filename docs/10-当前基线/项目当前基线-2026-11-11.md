## 当前产品方向

AtlasAI当前支持知识记录、原文保存、对象和关系查询、来源追溯、精确统计、更正、可恢复删除、恢复和历史查询。用户明确不要产品内人工确认流程；合法操作直接执行并返回回执，缺少必要目标信息时才澄清。

正式MCP已接入ChatGPT：调用Agent生成结构化参数，后端无LLM、无Graphiti、直接连接原Neo4j规范库。当前目录开发分支已快进合并并推送main，U00–U18与调整首发范围后的M00–M09完成。架构依据见[完整方案](../40-实施计划/AtlasAI知识管理MCP完整改造方案-2026-11-11.md)，扩展以[修改删除方案](../40-实施计划/AtlasAI知识管理MCP修改删除扩展方案与单元计划-2026-11-12.md)及用户延期永久清除的最新决定为准。

正式工具为get_context、find_records、get_record、query_records、get_sources、record_information、get_receipt、update_information、delete_information、restore_information、get_history。权限为read/record/update/delete/restore/history/bulk。永久清除不发现、不分派、不接受旧scope；归档、对象合并、审批、任意Cypher与工作流不开放。登录、角色、空间、来源、完整范围、版本和幂等校验继续保留。

## 目标架构

- 调用方 Agent 负责意图、提取、同义词扩展、查询参数和最终回答；后端只做确定性存取与校验。
- 后端不运行内部 Agent、LLM、Graphiti、embedding 或 reranker；不将这些能力作为错误回退或后台索引任务。
- 首版搜索采用字段、关系、关键词和 Neo4j 全文索引，不承诺自动语义检索。
- 新增、更正、删除、恢复的来源、规范内容、幂等回执与历史在Neo4j事务中保存。更正保留旧值和来源并退出当前统计；独立来源冲突仍保留陈述并排除冲突槽，不按先后覆盖。
- 数据库凭据、Cypher 和空间授权保留在服务端，不能把“直接连接 Neo4j”理解为 Agent 直接获得数据库访问权。

- 原数据库服务保留启动机制；旧语义卷、源码和历史备份受保护保留，不自动删除。它们不再承担正式MCP的模型调用或语义投影。

## 当前实施原则

1. 依赖、契约、隔离验证、真实客户端、报告、具体授权、Git合并推送、最终备份、迁移停旧及开写按顺序执行；不安排产品确认流程。
2. 正式MCP复用原规范库；候选数据独立，不因同域名自动合并或复制。
3. 对话理解必须在调用方 Agent 完成，服务端执行数据访问权限、schema、空间范围、事务、来源和幂等校验，不调用模型补判。
4. 已确认的方向不等于实施完成；功能开发、迁移演练和正式发布按完整方案分阶段验证及 Git 流程推进。
5. 原规范数据、来源和 ID 优先兼容；旧未执行操作不激活，旧语义库封存清理另行处理，不提前删除数据。
