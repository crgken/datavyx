## 1. 交付目标与工作单元定义

最终交付是调用 Agent 可使用的知识记录与查询 MCP：Agent 生成结构化参数，后端确定性校验、直连 Neo4j；无后端 LLM、Graphiti、embedding、reranker、语音/OCR 模型，无存量修改及产品内确认流程。

本计划把完整改造拆为 U00–U18 共 19 个工作单元。单元是可检查的开发或发布工作包，不对应独立微服务；目标仍是一套轻量 MCP 服务和既有规范 Neo4j。

每个单元必须具备：前置输入、明确代码/文档范围、可审阅交付、必要验证和完成条件。实现文件名可按仓库惯例微调，但单元职责、依赖及验收不能省略。

完成标准：

1. 前置条件已满足，变更只覆盖该单元及确有必要的公共契约调整。
2. 实现与确定性真值测试通过；报告区分单元、真实 Neo4j、协议、真实 ChatGPT 和生产验收。
3. 失败及边界情况明确，不以 mock 成功、后端模型修复或旧 Graphiti 回退代替。
4. 代码差异、相关文档、测试命令和结果可复核；未解决问题被明确列出。
5. 更新单元状态。只有到 U18 完成生产切换和上线验收后，才能把整体状态改为已上线。

## 3. 代码与验证目录规划

主要代码仍放在现有项目下，不创建新的本地工作树或另一套业务数据：

```text
knowledge-management-demo/
  mcp_backend/
    __main__.py / settings.py        # U02
    contracts.py / errors.py        # U01
    neo4j_repository.py             # U03
    auth.py                        # U04
    domain.py / source_rules.py     # U05
    catalog.py                     # U06
    records.py / search.py         # U07
    eligibility.py                 # U08
    query.py                       # U09
    ingestion.py / receipts.py      # U10
    server.py                      # U11
    diagnostics.py                 # U12
    migrations/                    # U03、U13
  tests_mcp/
    unit/ integration/ protocol/    # 按测试层次组织
    fixtures/                      # 合成输入与独立真值
  scripts/verify_mcp_*.py           # U12–U16 专用验证
  requirements-mcp.lock.txt         # U02，独立依赖
deploy/
  MCP 专用发布、服务、切换与恢复文件 # U14，实际名称实施时确定
```

文件边界服务于职责，不要求每个单元创建新类。新入口不能导入并初始化旧 Agent、Graphiti、索引 worker 或批准流程。测试显式指定 `tests_mcp` 等新范围，避免整个旧项目测试收集误触发历史模型/端到端脚本。

## 4. 第一组：开工、契约与运行基础

### U00 开工与 Git/环境边界

- **输入**：明确开始开发指令、当前工作区、完整方案及上线流程。
- **范围**：Git 跟踪清单、`.gitignore` 的精确放行、开发分支、环境和接入条件；不写业务实现。
- **任务**：保留已有改动；在当前目录创建 `codex/mcp-neo4j` 等分支；明确纳入版本控制的规则、设计、实现、锁文件及发布材料。核对 ChatGPT 自定义 MCP 权限、Auth0 配置权限、测试 Neo4j 与生产地址隔离。
- **交付**：开工清单、文件清单、环境命名和禁止生产写入的边界，标明仍被忽略的本地资料。
- **验证**：Git 能准确反映本次范围；密钥、真实数据、日志及无关历史材料未进入提交；测试配置误指生产时拒绝运行。
- **完成条件**：代码开发前置条件清楚，接入权限缺口已明确；不把“可以先用 mock”当成 ChatGPT 接入通过。

### U01 v1 工具与数据契约

- **输入**：U00；完整方案第 3–7 节及图谱上下文要求。
- **范围**：contracts/errors、schema 版本、输入输出例子和接口说明。
- **任务**：定义七个工具的严格参数与结果；structured/source_only、create/reference、文本/数值/关系、来源摘录、稳定请求 ID、目录/关系分页、统计口径和错误 code。身份、数据集、数据库地址、任意执行、确认及修改字段不进入模型可写契约。
- **交付**：v1 输入输出模型、合法/非法例子、字段和限额表；契约冻结后的版本变更规则。
- **验证**：合法样例可序列化往返；额外字段、未知版本、值与关系同时提供、孤立 ref、重复 ref、数值精度/长度超限和来源缺失均有明确结果。
- **完成条件**：下游单元不需要自行猜字段；契约覆盖完整流程且不引入确认工具。此阶段不连接生产或调用模型。

### U02 无模型运行骨架

- **输入**：U01。
- **范围**：新包入口、settings、独立依赖锁、最小启动/退出与存活检查。
- **任务**：只加载 Neo4j、认证、监听、限额和诊断所需配置；建立可替换的协议/服务装配边界，后续单元接入具体实现。无模型 env、模型 SDK、Graphiti、旧 mixin 或后台投影初始化。
- **交付**：可在干净环境启动/退出的骨架、锁定依赖及配置样例；尚未实现的业务接口不能伪报成功。
- **验证**：无模型密钥、未安装模型/Graphiti 包仍能启动；旧模型配置不会被新进程读取；数据库或认证必要配置缺失时明确失败，启动不修改业务知识。
- **完成条件**：新运行入口与旧 `demo.__main__` 完全分离，后续只增加确定性组件。

### U03 Neo4j 事务、约束与版本

- **输入**：U02。
- **范围**：repository 基座、连接/事务、唯一约束、migration 框架、数据版本和游标基础。
- **任务**：明确规范 KD 数据兼容模型；建立对象身份、记录请求键和持久 ID 约束；支持单事务写入、可重复迁移和版本锁。原始来源、事实与支持关系可独立表达，不需要审批节点或索引 outbox。
- **交付**：最小 Neo4j repository、迁移版本和升级检查、隔离 DB fixture；不继承旧 IndexStorage/PendingStorage。
- **验证**：真实测试 Neo4j 的提交/回滚、唯一约束并发冲突、重复 migration、连接失败和 revision 变化；异常不会留下半笔知识。
- **完成条件**：后续读写使用统一事务边界；未触碰生产库，也未处理真实迁移。

### U04 身份、OAuth 与空间权限

- **输入**：U03、U01 的授权边界。
- **范围**：auth、请求身份上下文、Auth0 发现与资源配置、空间成员映射。
- **任务**：验证 issuer/audience/scope/有效期及当前成员权限；仅允许 read/record；目录、ID、来源、回执和游标均绑定认证范围。空间选择只接受已授权标识。
- **交付**：可供服务和协议层共同使用的可信 Scope、OAuth 发现/回调接入说明、只读/可录入角色映射。
- **验证**：伪造 actor/dataset、过期/撤销身份、错误 audience、跨空间引用、只读用户写入、权限变更及猜测回执 ID；本地身份测试与真实 Auth0 接入结果分开记录。
- **完成条件**：后端无从模型参数取得权力的路径；真实 ChatGPT OAuth 在 U16 验收，不提前写为通过。

### U05 纯数据与来源规则

- **输入**：U01。
- **范围**：纯函数规则、身份规范化、来源/引用/值验证、Decimal 和指纹，不访问模型。
- **任务**：实现 create/reference 互斥、编号前导零与命名空间、原文摘录连续匹配、事实引用、单位来源、asserted/estimated/uncertain、语义限定和规范序列化。来源只证明认证提交，不证明事实真伪。
- **交付**：可直接单元测试的规则及真值 fixture；统一错误字段路径。
- **验证**：同名不同人、编号字符串、Unicode/空白、错误摘录、伪造单位、精度溢出、估计与精确同数值的差异、source_only 不生成假实体。
- **完成条件**：确定性规则清楚，可供目录、录入和查询共享；不添加单句意图判断或模型参数修复。

## 5. 第二组：图谱上下文与精确查询

### U06 目录与图谱约束上下文

- **输入**：U03、U04、U05。
- **范围**：catalog，`get_context` 的服务实现。
- **任务**：提供当前账号/空间、schema、类型/谓词/身份约束；支持按类别及名称筛选、稳定分页、catalog_revision/data_revision 与完整性。类型、谓词、对象事实分别有界，目录不携带整个图谱。
- **交付**：Agent 可用于语义对齐的目录结果及缓存边界说明。
- **验证**：超过一页、第一页缺少目标类型、空空间、未知但合法的新词汇、主客体类型、方向、单多值及单位规则；换账号/空间或权限变化不复用旧缓存。
- **完成条件**：不靠首次目录截断来推断词汇不存在；结果完全来自授权数据和规则，无 LLM 选择或总结。

### U07 候选、对象、局部关系与来源读取

- **输入**：U06。
- **范围**：records/search，`find_records`、`get_record`、`get_sources`。
- **任务**：编号/名称/类型/关键词候选，返回真实 ID；获取事实和一层邻接关系、来源与历史读取。实现受限字段匹配和经验证的 Neo4j 全文检索方式，不开放无界遍历或任意 Lucene/Cypher。
- **交付**：完整的“查候选 → 取局部详情 → 核对来源”服务；清晰的匹配模式、分页及版本元数据。
- **验证**：同名多候选、中英与符号、来源单独保存、邻居超过一页、历史内容、跨空间同名及猜 ID；全文模式不能跨空间先取全局前 N 再冒充完整候选。
- **完成条件**：原始资料与局部图谱可按需获取，Agent 不必也不会被默认发送整图；索引失败与无结果区分。

### U08 重复、冲突与统计资格

- **输入**：U03、U05。
- **范围**：eligibility、规范事实/来源支持的等价与冲突判定。
- **任务**：定义事实去重与各来源语义限定；多值关系去重；单值冲突保留全部陈述，相关统计排除冲突槽；估计、单位、旧失效及历史状态使用明确派生资格。
- **交付**：共享资格计算和原因码、与旧 confirmed/review_status 的兼容解释，不产生人工批准语义。
- **验证**：先后顺序不决定真假、同值不同确定性、不同来源、单值矛盾、多值不同目标、对象计数与属性冲突分离；历史旧提案不能成为有效事实。
- **完成条件**：录入与查询不各写一套冲突解释，精确统计可独立核对排除原因；不改写或删除原陈述。

### U09 结构化精确查询

- **输入**：U07、U08。
- **范围**：query、受限条件编译、`query_records`。
- **任务**：实现 LIST/COUNT/GROUP/SUM、方向/关系/字段条件、单位、固定精度及稳定分页；使用参数化模板。聚合范围与明细分页分开表达，游标绑定空间/筛选/revision。
- **交付**：结构化查询服务、匹配/参与/排除口径及可复核结果；不返回模型生成的数字或自然语言补全。
- **验证**：超过一页仍完整统计、同对象多来源不重计、缺失/估计/冲突、空集合、不同单位、浮点风险/溢出、跨页变化、恶意操作符/表达式和资源超限。
- **完成条件**：独立真值数据能核对全部运算；不能直接把旧 `_query` 的人工确认兼容解释搬成新规则。

## 6. 第三组：直接录入、MCP 与完整集成

### U10 原子新增、幂等与回执

- **输入**：U06、U08，以及 U03/U04/U05 基础。
- **范围**：ingestion/receipts，`record_information` 和 `get_receipt`。
- **任务**：保存 structured/source_only；合法引用既有对象并追加来源与事实；事务内重查权限/身份/谓词约束。以身份、客户端、空间和稳定 request_id 约束唯一请求，数据、审计、版本及回执同事务提交。
- **交付**：直接记录及回执读取服务；成功、冲突资格、原文单独保存和真实新增数量均明确。
- **验证**：正常保存、相同正文重放、同键异正文、并发同键、唯一标识竞争、来源检查失败、半途 DB 异常、提交成功但响应丢失、回执未发现后同键重试；sources/facts/receipt 无半笔残留。
- **完成条件**：返回 recorded 时数据库已提交；无 KDDraft/KDApproval、预览、confirm、后台模型或 Graphiti outbox。参考身份和来源失败时整笔回滚，而不是自动合并或批准。

### U11 MCP 协议与工具适配

- **输入**：U04、U07、U09、U10；U01/U02 的契约及装配。
- **范围**：server、HTTP/MCP 入口、元数据、发现/认证挑战、错误映射。
- **任务**：将七个服务注册成 MCP 工具，公布准确 input/output schema 与读写标注，提供结构化结果和简短文本；集成 OAuth、协议版本协商、请求限额与退出清理。
- **交付**：可供 MCP Inspector/真实客户端接入的端点及工具清单。
- **验证**：真实协议握手/列工具/调用、未登录、token 权限、非法字段、工具异常、断连、schema 与实际返回一致；工具清单不存在修改、审批或任意执行后门。
- **完成条件**：无自定义 UI 也能使用全部工具，后端不生成业务回答；这不替代 U16 的真实 ChatGPT 行为验收。

### U12 完整隔离集成与运行防线

- **输入**：U11。
- **范围**：tests_mcp 集成/协议测试、verify_mcp 脚本、diagnostics、资源与依赖检查。
- **任务**：串起上下文 → 引用/新增 → 回执 → 查询 → 来源；补足跨服务错误、并发、限额、超时与运行指标。用合成真值和实际隔离 Neo4j 验证，不把 FakeStore 当数据库验收。
- **交付**：可重复运行的测试入口、覆盖报告、日志脱敏检查、依赖/出网约束结果及未覆盖项。
- **验证**：去掉全部模型 key、未安装模型/Graphiti 包、阻止模型端点访问仍通过；目录和事实分页、对象/来源权限、冲突计数、响应丢失重试和多账号隔离整体成立。
- **完成条件**：所有规定关键测试通过。测试失败有明确根因，不通过跳过测试、减少范围或旧模型降级来“通过”。

## 7. 第四组：数据兼容、部署与真实客户端

### U13 历史数据兼容与迁移验证

- **输入**：U12。
- **范围**：版本化迁移、只读盘点/差异核对、恢复工具及历史数据 fixture。
- **任务**：兼容旧规范 ID、对象/事实、来源、状态、单位与成员；旧未执行/已取消提案不激活，归档/撤回数据不自动恢复。列出新冲突规则导致的合理统计差异，不用后端模型重抽历史消息。
- **交付**：幂等迁移与 preflight/verify/恢复说明，在隔离历史 fixture 上的兼容报告。
- **验证**：无历史数据、旧字段缺失、多来源、不精确数值、旧手工状态、重复迁移和迁移中断；原文及 ID 不丢失，冲突数据不静默删改。
- **完成条件**：迁移逻辑可在副本运行且有明确失败/恢复路径。真实生产副本演练在 U15 完成；本单元不动正式库。

### U14 MCP 专用发布与退役工具

- **输入**：U12，结合已确定的数据迁移接口；若 U13 契约改变须同步验证。
- **范围**：Git 候选打包、MCP 服务/配置模板、独立 venv、健康、旧入口/worker 切换与恢复脚本。
- **任务**：适配旧发布边界，发布新 MCP 入口和独立依赖锁；不安装旧模型依赖或启动旧 API。包来自明确提交，记录清单和校验值，复用已验证包；旧网页先采用可回滚的静态迁移说明。
- **交付**：受控测试部署、正式应用发布和恢复的操作入口及说明；密钥不入包。
- **验证**：候选篡改/版本不符、缺失配置、迁移失败、服务启动失败、健康失败和恢复路径；旧 session 返回 401 不能作为 MCP 健康证明。脚本不触发 Flutter 构建或非必要停库。
- **完成条件**：在隔离环境验证发布与恢复；正式入口切换只能由 U18 执行。

### U15 服务器候选与数据副本演练

- **输入**：U13、U14；开发分支已提交推送，候选包锁定。
- **范围**：服务器受保护测试路由、隔离配置/进程/Neo4j、一致性数据副本及演练报告。
- **任务**：部署候选，不覆盖生产路由；以一致性且经过授权的备份建立数据副本；完成迁移、差异核对、重启、失败和恢复演练。若获取新副本需要停库，另行安排已授权窗口，不擅自停线上。
- **交付**：候选 commit/包 hash/依赖锁、服务器校验、迁移差异、恢复结果及维护时长实测依据。
- **验证**：规范数据和来源保持、旧风险提案未激活、无第二语义库依赖、无模型请求；生产配置/数据未被候选修改。
- **完成条件**：服务器候选和实际兼容演练通过。没有可安全使用的数据副本时保持未完成，不能以合成数据库报告冒充真实兼容。

### U16 真实 ChatGPT 闭环

- **输入**：U15、可使用的目标 ChatGPT 与 Auth0 账号配置。
- **范围**：真实客户端测试提示集、授权配置核对和结果追踪，不新增业务能力。
- **任务**：测试直接/间接表述、追问、查目录/候选/局部关系、结构化录入、source_only、查询、来源、同名和冲突、范围外修改请求、保存结果未知后的回执恢复。
- **交付**：各案例实际工具选择/参数/返回/结果、权限行为和客户端提示的报告；使用合成或获授权的隔离数据。
- **验证**：Agent 不编造已有 ID、目录截断不引发同义词乱建、局部上下文不冒充全量统计；正常录入无 AtlasAI 批准环节；ChatGPT 重试能核对原 request_id/回执；后端不调用模型。
- **完成条件**：真实 ChatGPT 完整业务闭环通过。没有客户端权限时记录阻塞，不拿 API Playground 或 Inspector 代替，U17 不得宣称可发布。

## 8. 第五组：Git 发布与正式上线

### U17 发布审阅与 main 锁定

- **输入**：U16 及全部前置单元通过报告。
- **范围**：发布说明、最终 diff、迁移/维护/备份/切换/回滚清单、Git 合并与候选一致性。
- **任务**：提交具体可审阅报告，明确测试及未覆盖项、候选版本、停旧范围和恢复步骤。用户明确正式发布后再合并并推送 main；若已授权同一具体发布，不重复请求。
- **交付**：发布授权与版本对应记录、origin/main commit、候选清单与 hash、最终操作清单。
- **验证**：候选和待部署 main 运行内容一致；合并产生运行变化则重新验证受影响项并锁定候选；不混入未提交文件或与原候选不一致的包。
- **完成条件**：生产动作所需条件齐备，仍未实际停旧、迁移或切入口。

### U18 生产切换与上线验收

- **输入**：U17、已授权维护窗口及已验证恢复材料。
- **范围**：正式写入屏障、一致性备份、必要迁移、新 MCP 接管、旧模型路径停用、开放写入与上线记录。
- **任务**：严格执行上线流程第 9–10 节：保护在途请求 → 备份 → 应用已测版本/迁移 → 限制开放验证 → 停旧切新 → 开放新写入 → 上线复核。
- **交付**：实际部署版本、迁移版本、备份/恢复引用、健康及真实客户端最小闭环结果，更新线上现状与项目基线。
- **验证**：新认证/工具/保存/回执/查询/来源和版本正确；旧自然语言/语音/修改/确认接口及 Graphiti worker 已停用，无后台模型请求。必要生产小样本使用单独标识和空间，不混入用户业务数据。
- **完成条件**：生产切换与验收完成才能标记已上线。开放新写入后回滚不能恢复旧卷丢掉新数据；旧语义容器/卷永久删除仍不属于本单元。

## 10. 里程碑与执行顺序

| 门槛 | 单元组合 | 达到后说明 |

| G2 业务核心可用 | U06–U10 | 图谱上下文、读取、资格、精确查询和直接新增成立 |

| G6 正式上线 | U17–U18 | 已推送 main 的已测候选完成正式切换与上线验收 |

建议推进顺序：U00 → U01 → U02 → U03 → U04；U05 依赖 U01，可在基础环境准备阶段完成。随后按依赖完成 U06/U07/U08、U09/U10，再接 U11/U12，最后按 U13/U14 → U15 → U16 → U17 → U18 推进。依赖图允许独立工作交错，但本计划不自动创建并行任务或代理。

每个单元通过后，可按清晰变更边界提交开发分支；相关单元可合并成一次可审阅提交。只有 G3 之后才锁定服务器候选，不对每个小改动重复打包部署。main 内容变化、依赖/迁移变化或失败修复时，重新验证受影响项；没有新变化和疑点时不反复运行完整套件。

具体工期以 U00 的环境/账号核对及基础单元实际结果再评估，不将需要外部授权的等待时间伪装为确定开发工时。

真值 fixture 至少覆盖：同名对象、明确重复编号、超过一页的类型/关系/对象、多来源同值、同值不同确定性、单值冲突、多值关系、source_only、不同单位、缺失字段、先提交后断连、并发同键和跨空间 ID。统计预期由人工构造数据及独立核对得出，不由被测查询函数生成自己的预期答案。

测试报告不记录密钥或用户正文。必要历史数据演练材料只保留在受保护位置，Git 内只放合成 fixture、脚本及脱敏摘要。

## 12. 进度记录与变更规则

单元状态依次使用“未开始 / 进行中 / 验证中 / 已完成”；存在外部条件或错误时记录具体阻塞和已做工作，不伪报完成。每次更新至少记录单元 ID、变更范围、commit 或待提交差异、验证命令/结果、遗留项和后续依赖。

契约或架构范围需要变化时，先更新完整方案和受影响单元，再实施；不得在调试中加入后端 LLM/Graphiti、审批页面、覆盖旧事实、任意 Cypher 或新工作流作为捷径。

开发单元中的校验失败由结构化错误及必要参数纠错处理，不为每个单元或每条业务记录增加人工批准。只有流程规定的开始开发和正式发布授权节点适用；已有明确授权不重复请求。

本轮产出为这份开发计划及关联文档更新。当前 19 个单元均未开始，没有创建开发分支、安装依赖、运行构建、修改实现代码或操作生产。
