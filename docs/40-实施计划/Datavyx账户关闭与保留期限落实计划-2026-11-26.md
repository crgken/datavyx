# Datavyx 账户关闭、备份和日志保留实施计划

2026-11-26。用户已确认保留期限、授权落实管理流程、支持/条款/隐私页面及验证后的公开插件准备；不重复构建前端。已有.gitignore、11-13报告与website改动原样保留，不覆盖或混入无关提交。

## 确认规则和安全边界

- 账号存续期间保留知识、原文、关系、更正历史及可恢复删除状态；不新增按30天自动永久删除普通记录的行为。
- 经支持邮箱核验的账户关闭：先停用该账号的Datavyx访问，30天内清理活动个人数据/绑定；备份最长30天滚动保留，通常从核验请求起最长60天退出活动系统及备份。
- 技术/安全日志30天，不含原文/完整参数/令牌；必要支持工单记录结案后12个月。
- 关闭通过受保护主机管理命令执行，不增加公共MCP工具，不使用用户token/产品确认卡。支持身份核验不等同于逐条知识操作审批。
- 不执行此前被客户端拒绝的15项合成purge请求。历史备份首次到期处置必须有精确盘点、边界、有效新备份与验证，不盲删目录或卷。

## 最小实现路线

1. 在现有持久ledger父目录下增加独立account-state目录、专用密钥和签名关闭记录，置于数据库备份/运行包之外。正式与候选同主机共享该关闭身份屏障，生产启动在目录/签名不完整时fail closed。
2. 所有身份解析、空间创建及每次事务授权检查账户关闭，既有token与重新登录均不能绕过。数据库同时保存最小关闭标记；备份恢复后以外部签名记录为准恢复限制和清理。
3. 管理流程持久记录匿名化actor、核验工单的不可逆引用、收到时间、活动数据截止与备份截止、各环境处理结果。私有空间需由真实成员/owner与workspace.kind证据确定；不自动清理共享空间内容，不删除其他成员。未知/旧代单拥有者空间单列为人工分类阻断，不猜测所有权。
4. 新备份在所有数据集写锁及元数据锁下取得一致逻辑快照，包含当前生命周期和成员记录；新格式支持空隔离库恢复验证。备份包含恢复前必须核验关闭/清除ledger的门槛；签名关闭记录与密钥不能随数据库卷覆盖。
5. 轮转只作用于已登记、hash核验、处于固定根目录下的常规文件/目录；不跟随symlink、不删除活动数据库/密钥。到期旧备份只在已验证可恢复的新备份存在后处置；受保护清单记录结果与失败，不静默忽略过期副本。
6. systemd定时执行备份/轮转/关闭重试，首次仅安装只读审计，实际破坏性操作需经过合成测试和具体生产发布范围核验。技术日志的持久周期和轮转必须按真实文件/journal设置验证，不用磁盘总大小代替期限。
7. 支持邮件不整箱扫删。管理流程记录工单关闭时间和明确消息标识；按12个日历月计算到期，通过受支持的邮件端流程只处理明确归档的支持工单，保留未结案/无关闭日期/必要保全的记录。没有邮件凭据或分类证据时标为待配置，不声称已自动清理。
