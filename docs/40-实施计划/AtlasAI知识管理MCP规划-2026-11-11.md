# AtlasAI 知识管理 MCP 规划入口

日期：2026-11-11  
状态：用户已明确改造方向，完整方案已整理；尚未开发、迁移或上线。

## 当前方案

以[完整 MCP 改造方案](AtlasAI知识管理MCP完整改造方案-2026-11-11.md)为唯一详细实施依据，本文件保留原链接作为简要入口。

- 调用方 Agent 负责理解、提取和生成结构化记录/查询参数。
- 后端不运行 LLM、内部 Agent、Graphiti、embedding 或 reranker，直接连接现有 Neo4j 规范数据。
- 仅记录与查询；有效新增直接保存并返回真实回执，无预览、待确认标志、批准页面或确认/执行工具。
- 不提供更正、覆盖、合并、删除、归档、恢复、审批、Frappe 业务操作或任意 Cypher。
- 后端保留身份与空间权限、schema、来源摘录、合法引用、冲突资格、幂等、事务和精确统计校验。
- 首版采用字段匹配、结构化筛选、关系查询和关键词/全文搜索，不承诺语义召回。
- 不自动合并同名对象，不覆盖冲突事实，不将不确定或冲突内容混入对应精确统计。

## 工具与实施

首版工具为 `get_context`、`find_records`、`get_record`、`query_records`、`get_sources`、`record_information`、`get_receipt`。后者只核对保存结果，不是审批任务；各工具的契约、限额和规则见完整方案。

按“契约与依赖隔离 → 身份及只读 → 直接记录 → 数据兼容演练 → 真实 ChatGPT 闭环 → Git 发布”推进。切换计划必须覆盖旧自然语言接口、Graphiti worker、第二语义库和旧网页；不提前删除数据，也不重新构建 Flutter。
