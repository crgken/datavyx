# 知识管理 MCP 采用 Agent 结构化输入与 Neo4j 直连

日期：2026-11-11  
决策状态：用户已明确采用此方向，待实施；不是上线记录。

## 决策

- 调用 Agent 负责自然语言理解、结构化信息提取、查询条件及回答生成。
- 后端是确定性的 MCP 记录与查询服务，直接访问现有 Neo4j 规范数据。
- 后端不运行 LLM、内部 Agent、Graphiti、embedding 或 reranker；不保留模型失败回退链路。
- 仅新增记录与查询；无预览、待确认、人工批准、存量覆盖、更正、删除、归档或恢复接口。
- 保留登录、空间隔离、来源、schema、身份、幂等、事务和精确统计校验；它们不等于操作确认。

## 取代的旧假设

取代早期 MCP 规划中“后端保留提取/问答 Agent、Graphiti 语义检索或未来可直接复用全部存量服务”的假设。Frappe 方向仍保持已归档状态。

当前线上还运行旧模型、Graphiti 及存量受控修改流程；本决策不表示这些依赖已被停用。新服务必须拆开旧 Store/索引/批准耦合，不能只包装旧聊天接口或删除依赖包。

## 后果与实施门槛

- 首版检索为结构化条件、关系及关键词/全文，不承诺自动语义召回。
- 同名不自动合并，单值冲突追加来源并显式展示，相关精确统计排除冲突槽。
- 原业务记录和来源优先兼容，旧未执行提案不转换成有效知识。
- Graphiti worker、第二语义库和旧网页需有明确切换/封存方案，不能提前删库。
- 最终旧模型入口和后台 worker 必须按方案停用，不能保留后台模型调用却宣称改造完成。
- ChatGPT 真实连接、权限、无确认写入、精确查询、幂等及无模型网络依赖全部通过后，才进入 Git 正式发布。
