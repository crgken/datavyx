# MCP 客户端自助接入后端开发报告

日期：2026-11-13。状态：本地后端改造及隔离验证完成，未发布、未修改生产配置或 Auth0 租户设置。

## 授权与范围

用户明确授权“允许所有符合规则的 MCP 客户端自助接入，用户登录后自动创建独立空间，确认方案，开始改后端”。开发分支为 `codex/mcp-self-service`。

本轮实现 OAuth 资源服务的客户端准入模式；Auth0 继续负责客户端登记、登录、用户授权和签发令牌。没有增加客户端登记接口、Management API 凭据、共享用户 Secret 或产品内操作确认流程。

## 实现

- 新增 `MCP_AUTH_CLIENT_POLICY`：`allowlist` 是兼容默认值；`authenticated` 接受指定 issuer 对当前 audience 签发、带有效用户身份和所需 scopes 的访问令牌，不再要求每个 Client ID 预先登记在后端环境变量中。
- 自助模式可省略 `MCP_AUTH_CLIENT_IDS`；此模式下保留的 ID 列表不限制准入。拼错模式、空白 ID 及 `*` 通配符均被配置校验拒绝。仅清空旧白名单不会自动开放。
- 两种模式继续校验 RS256 签名、issuer、audience、有效期、有效用户及 Client ID、声明一致性、可选 organization、scopes、撤销记录和当前空间成员角色。拒绝 `@clients` 机器身份及 `gty=client-credentials`。
- 新用户首次合法工具调用未指定空间且无已有成员关系时，复用现有事务逻辑，创建 `personal:<digest(issuer, sub)>` 和 owner 成员关系。相同身份跨客户端复用空间；不同用户隔离。客户端不能通过提交 actor、邮箱或空间 ID 获得其他用户的数据。
- 已有成员关系保留，不自动加入 `knowledge-demo`，被禁用的个人空间成员关系不会通过重新连接恢复。个人空间不会因客户端登记而创建，只会在通过授权的工具调用时创建。
- 11 个公开工具、七权限和永久清除延期边界保持有效。无新 schema 迁移、依赖或前端构建。

自助模式并不认证客户端的软件品牌，也不声称令牌一定来自 DCR；预注册和 DCR 客户端都可使用。准入依据是可信 issuer 的有效用户委托 API 令牌。PKCE、授权码/回调、DCR 限制及第三方 API grants 由 OAuth 客户端和 Auth0 执行。

## 候选接入及发布前待办

1. 在隔离候选服务设置 `MCP_AUTH_CLIENT_POLICY=authenticated`，保留原 issuer 与候选专用 audience/resource，运行配置检查。无需分发 Client Secret。
2. 核对 Auth0 DCR 开关、Resource Parameter Compatibility Profile、面向第三方客户端可用的登录连接，以及登录/注册策略。
3. 明确选择第三方应用默认 User-Delegated scopes；M2M 不开放。旧租户还需核对 strict DCR 模式及默认第三方 client grant。不要修改租户全局 Default Audience 作为兼容性修复。
4. 两个真实用户在 Claude 或其他支持的客户端中添加候选 URL，完成各自 OAuth，核对首次个人空间、写入/读回、跨用户拒绝、刷新与重新连接。客户端配置与 Auth0 DCR 本轮未实际操作，尚不能声称真实用户可自助连接。
5. 形成真实候选验收报告，取得具体生产发布授权后，再按 Git 和生产发布流程部署代码、设置正式 `MCP_AUTH_CLIENT_POLICY=authenticated`；不重复构建前端。

回退准入时恢复 `allowlist` 和已批准 Client ID 后重启即可；这不会删除新增个人空间或内容。新写入存在时仍禁止旧库整卷覆盖或重开旧 API。
